# StressFree AI — mobile app

Expo / React Native client for StressFree AI. Android and iOS from one codebase.

## The one architectural rule

**The app never holds a model API key, and never decides whether a message is a
crisis.** Every reply is generated by the Next.js server in `../`, which runs the
deterministic safety layer first and only then calls a model. The phone talks to
that server over `POST /api/chat`.

That means:

- moving the safety lexicon (or the prompt) forward is a server deploy, not an
  app-store release;
- if the server decides a message is a crisis, the app opens a full-screen
  helpline panel and stops being a chat app for a moment;
- helplines come from `GET /api/resources`, so the web and mobile numbers can
  never disagree. The app caches the list, and falls back to Tele-MANAS 14416,
  112 and Childline 1098 with no network at all.

## Requirements

- Node 20+
- The web app running somewhere (locally or deployed), because this is a client.

## Run it

```bash
cd mobile
npm install
cp .env.example .env                 # then set EXPO_PUBLIC_API_BASE
npx expo start
```

Then press `a` for an Android emulator, `i` for the iOS simulator, or scan the
QR code with the Expo Go app.

`EXPO_PUBLIC_API_BASE` must be reachable **from the device**, not just from your
machine. `http://localhost:3000` works for a simulator on the same computer; a
physical phone needs your machine's LAN IP or the deployed URL.

## Checks

```bash
npx tsc --noEmit            # typecheck
npx expo lint               # lint
npx expo export --platform android   # verify it actually bundles
```

## Structure

```
src/
  app/                 Expo Router routes
    _layout.tsx        root layout + the consent gate
    (tabs)/            the bottom tab navigator
      index.tsx        Talk: chat against the server
      tools.tsx        Calm: breathing and grounding, fully offline
      safety.tsx       Safety: limits, helplines, settings, erase
  components/          Onboarding, CrisisPanel, HelplineCard, ui primitives
  lib/
    api.ts             the only place that calls the server
    resources.ts       helplines: server, then cache, then emergency fallback
    profile.tsx        consent, language, memory, erase
    i18n.ts            English / Hindi / Gujarati, typed against English
    storage.ts         AsyncStorage keys, all of them removable at once
    theme.ts           the same palette as the web app
```

## What mobile deliberately does *not* do

- No accounts, no analytics, no tracking. Consent and chats live on the device.
- No on-device crisis detection. It would drift from the server's and would be
  the one that gets it wrong.
- No claim to be a therapist anywhere in the UI.

## Building for the stores

```bash
npx eas-cli@latest build --profile production --platform android
npx eas-cli@latest build --profile production --platform ios
```

Publish only after the web app's safety page, privacy page and launch checklist
in the root README are done. A mobile app reaches people who will not read a
website first.
